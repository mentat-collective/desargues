# Layer effects (fosfora `.pfx`)

fosfora's effect **catalog** lists full layer effects, each a `.pfx` JSON file
beside a WGSL layer shader. This is separate from trama nodes
(`doc/trama-layers.md`), which live in a chain. `desargues.wallpaper.emit` with
`:target :pfx` (`desargues.wallpaper.pfx`) writes both files. The WGSL body
(helpers, `desargues_field`, `fs_main`) is generated by the same code as
`:trama`. Only the packaging and the slot that carries the rate integral differ.

## Emit a layer effect

```clojure
(emit/emit! {:id :quasicrystal :title "7-fold quasicrystal"
             :target :pfx
             :pfx {:name "Seven Fold"            ; catalog title + preset key (default :title)
                   :author "tessera"             ; default "tessera"
                   :description "..."            ; default :description, then :title
                   :category "pattern"}          ; default :category, then "pattern"
             :form fld/quasicrystal :period 12
             :params [['scale {:default 3.0 :min 1.0 :max 8.0}]]}
            "out/effects")
;; => {:ok [".../out/effects/quasicrystal.pfx" ".../out/effects/quasicrystal.wgsl"]}
```

Use a folder separate from the trama folder, because fosfora routes a `.wgsl`
in a trama folder to the trama reloader.

## The `.pfx`

It has exactly these keys, in this order:

```json
{ "name": "Seven Fold", "author": "tessera", "description": "7-fold quasicrystal",
  "shader": "quasicrystal.wgsl", "category": "pattern",
  "inputs": [ {"type":"Float","name":"loop_rate","default":1.0,"min":0.0,"max":4.0},
              {"type":"Float","name":"scale","default":3.0,"min":1.0,"max":8.0} ],
  "rates": ["loop_rate"] }
```

- `shader` is a path relative to the `.pfx`, so the two files sit side by side.
- `inputs` holds the same ParamDef objects as the trama `params`: `loop_rate`
  first, then the layer's `:params` in declared order. That order is
  append-only, as in `doc/trama-layers.md`.
- Golden file: `test/desargues/wallpaper/golden/quasicrystal.pfx.json`.

## Rate delivery (the difference from trama)

In a `.pfx`, the rate param's own slot keeps its **raw** value. Its running
integral goes into an **extra slot after all packed params**:

| slot | holds |
|---|---|
| 0 | `loop_rate`, raw (not read by the shader) |
| 1 .. N-1 | the layer's params, declared order |
| N | the integral of `loop_rate`: `phase = fract(param(Nu) / period)` |

With params `[loop_rate fermi_level contour_step sharpness lattice_scale]`,
N is 5 and the shader reads `fract(param(5u) / 16.0)`. Each Float takes one
slot. The params plus the rate slot must fit in 16 slots, so a layer can have
at most 14 params, where trama allows 15. `pfx/rate-slot` returns N.

## The shader

The shader is the trama body minus the trama-only parts: no `/*! trama`
manifest and no blend-hint comment, only one plain comment line. It declares
the same `fs_main(@builtin(position) frag_coord: vec4f) -> @location(0) vec4f`,
and every helper carries the `desargues_` prefix. Output is opaque. fosfora's
preamble supplies `u` and `param(i)`. The shader ignores the feedback texture.

## Display names

Presets save effects by name, so `name` must not equal any of fosfora's built-in
effect names. `pfx/builtin-names` holds all 60 of them. The comparison ignores
case and collapses runs of whitespace. Earlier copies of the list were spaced
ambiguously; the fosfora session confirmed that **"Raster" and "Stress" are two
separate names**, and no built-in is called "Raster Stress".

## Refusals

| err | when |
|---|---|
| `:pfx/too-many-slots` | loop_rate + params + the rate slot exceed 16 (more than 14 params) |
| `:pfx/name-collision` | the display name is a fosfora built-in |
| `:pfx/bad-name` | the display name is blank |
| `:trama/*`, `:layer/*`, `:field/*` | as for `:target :trama` |

## Validation

`test/desargues/wallpaper/pfx_test.clj` covers:

- the golden `.pfx` file and its key order;
- the index of the extra rate slot;
- the slot cap, including the 15-param layer that trama accepts and `.pfx` refuses;
- name collisions;
- the shader structure;
- CPU parity of the WGSL tree against the JVM shader;
- naga validation behind the trama stub preamble, when naga is found.

fosfora validates every effect itself through its own loader.
